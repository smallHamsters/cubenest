## 2. 안 보이는 나무 6종 — 정의·규칙·알고리즘 〔핵심〕

교과 "안 보이는(숨은) 쌓기나무" = 겨냥도에서 다른 큐브에 가려 **윗면이 보이지 않는 열**. 6종은 (제시물 × 질문)의 조합.

### 2.1 불변 규칙 — visibleTop (교과서 검증 완료)
```
heightMap h(x,z) = 각 (x,z) 열의 높이.
visibleTop(x,z)  ⟺  h(x+1, z+1) <= h(x,z)      // 앞대각이 '더 높을 때만' 가려짐. 동일높이=보임(<=)
숨은 열 hiddenColumns = footprint − visibleTop  = { (x,z) : h(x+1,z+1) > h(x,z) }
```
- **⚠ `<`가 아니라 `<=`** — 평지 2×2(동일높이 대각)를 숨음으로 오판하는 버그를 잡은 규칙. 교과서 70쪽 1·2번 + 엣지 케이스로 검증됨.
- **A-f 종류 수(enumerate):** 숨은 열의 높이 t는 `1..(D-1)` 가능(D=앞대각 높이, t<D여야 숨음 유지). 가짓수 = Π(D−1), cap 6.

### 2.2 6종 규격 (제시 → 질문 → 답 → 서버계산)
| 서브 | 이름(랜딩) | 제시(given) | 질문 | 답형(form) | 서버 answerKey |
|---|---|---|---|---|---|
| **A-a** | 숨은 나무 판단 | 겨냥도+위모양 | 숨은 나무 있나? | `bool` | `hasHidden(hmap)` |
| **A-b** | 숨은 나무 칸 찾기 | 겨냥도+위모양 | 숨은 칸 모두 | `markCells` | `hiddenColumns(hmap)` (["x,z"]) |
| **A-c** | 개수(위+수) | 위에서 본 수 | 총 개수 | `num` | `count`(=Σh) |
| **A-d** | 개수(삼면도 최대최소) | 삼면도 | 최대/최소/차 | `num` | `reverseCounts`(min/max/diff) |
| **A-e** | 개수(층별) | 층별 모양 | 총 개수 | `num` | `count` |
| **A-f** | 여러 가지 종류 | 겨냥도+위모양 | 몇 가지? | `num` | `enumerateByVisible(hmap,6)` |

- **정답 은닉:** A-a/b/f는 겨냥도 기반이라 정답이 보이면 안 됨. **클라 `renderIso`가 painter's algorithm(뒤→앞)이라 숨은 열을 자동 가림** → 정적 iso로 은닉 성립(hidden은 3D 회전 비활성). **별도 서버 renderIso 불필요**(검증됨).
- **난이도별 서브 pool(gen):** 중 = A-a·b / 상 = +A-c·d·e / 최상 = +A-f. (hidden 지원 등급 = 중~최상.)
- **생성 제약(regen):** A-b=hasHidden 有 / A-d=reverseCounts 범위(max>min) / A-f=enumerate 2..6.

### 2.3 계산 모듈 `cubenest-hidden.js` (isomorphic, 서버채점+클라해설 공용)
API: `visibleTopFootprint(hmap)` · `hiddenColumns(hmap)` · `hasHidden(hmap)` · `layersToShape(layers)` · `layersCount(layers)` · `enumerateByVisible(hmap,cap)`. hmap=`{"x,z":h}`.
재사용(core): `heightMap`·`reverseCounts`·`reverseShapes`·`silhouettes`.

## 3. 데이터/제어 흐름

```
[랜딩 quiz/index.html]  카드/아코디언 클릭
   → run/?type=hidden&sub=A-x&lv=<codes>&n=<n>
[run.js] loadParams(sub) → api.generate({theme:'hidden', levels, seed, n, sub})
   → [api-client.js] POST /generate (flat body)
      → [generate/index.ts] buildProbs({type,levels,seed,n,edu, sub: body.sub})
         → [gen-adapter buildProbs] genSession({..., sub})
            → [cubenest-gen genSession] genProblem({..., sub})  // o.sub 강제(정규식 A-[abcdef])
               → hidden 분기: sub별 regen + out.{sub,hcols,hasHidden,count,rc,which,kinds}
         → questionFor(pr): q.{sh, sub, (A-d)which/rc, (A-f)kinds}  // 정답(hcols/hasHidden) 미전달
   ← 응답 _gp(=questionFor) → run이 pr 빌드·렌더
[제출] run → api.grade({id,gsig,answer,params:GRADE_PARAMS()})  // params 래핑, sub 포함
   → [grade/index.ts] buildProbs({..., sub: params.sub}) → answerKeyFor(sub) → checkAnswer
```

**중요 비대칭:** generate는 **flat body**(`body.sub`), grade는 **params 래핑**(`params.sub`). (이 불일치로 500 `params is not defined` 발생했었음 — 해결됨.)
**gsig/paramsHash에 sub 미포함** — 하위호환 위해 의도적. run이 generate·grade에 **같은 sub**를 보내 재생성 일치. (sub는 보안 대상 아님.)

## 6. 배포 절차 & 함정 〔반복 사고 지점〕

### 6.1 `_shared` export/import 규약 (503 BOOT_ERROR의 주범)
- 서버 `_shared/*.js`(core·gen·gen-config·hidden)는 **원본 IIFE(globalThis.CubeNest 세팅) + 맨 끝 ESM export** 형태여야 함:
  ```js
  // [서버 전용] ESM named export
  export const gen = globalThis.CubeNest.gen;   // core/genConfig/hidden 동일 패턴
  ```
- `gen-modules.ts`가 **값 import**로 이들을 가져와 번들 포함 보장 + **로드 순서** 강제:
  ```ts
  import { core } from "./cubenest-core.js";
  import { genConfig } from "./cubenest-gen-config.js";
  import { hidden } from "./cubenest-hidden.js";   // gen보다 먼저 (genProblem이 참조)
  import { gen } from "./cubenest-gen.js";
  export { core, gen, genConfig, hidden };
  ```
- **파일 추가 시 export 안 붙이면** → `does not provide an export named 'x'` 부팅 크래시.
- **파일 참조하는데 _shared에 없으면** → `500 BOOT_ERROR`.
- node로 `require` 시 ESM export 줄 때문에 실패하는 건 **정상**(Deno는 ESM). node 검증은 export 없는 원본으로.

### 6.2 재배포
```powershell
supabase functions deploy generate
supabase functions deploy grade
```
- `_shared` 변경은 **generate·grade 둘 다** 재배포.
- "함수 하나만/파일 하나만" 배포 불가 — 함수 단위.
- 재배포 후 `config.toml`의 `verify_jwt=false`가 빠지지 않았는지 확인.

### 6.3 진단
```powershell
curl.exe -i -X OPTIONS "https://jtniutmexokswdpxkjof.supabase.co/functions/v1/generate" -H "Origin: http://127.0.0.1:5500" -H "Access-Control-Request-Method: POST"
```
- **204** = 정상 / **401** = verify_jwt 켜짐 / **500·503 BOOT_ERROR** = 부팅 크래시(로그 확인).
- 대시보드 Functions Logs에 실제 크래시 파일·메시지가 찍힘.

### 6.4 generate vs grade 요청 형태 (500 `x is not defined` 주의)
- generate: `body.theme`, `body.sub` (flat).
- grade: `params.theme`, `params.sub` (body.params 래핑).
- 새 필드 추가 시 **각 파일의 접근 방식에 맞춰** 넣을 것.
