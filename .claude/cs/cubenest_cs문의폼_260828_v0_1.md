# CubeNest CS 문의 구글폼 — 작성 명세 (260828 v0.3)

푸터 "문의하기"가 여는 **서비스 전반 CS 폼**. 이 문서 하나로 폼을 그대로 다시 만들 수 있게 썼다.
폼을 고치면 이 문서도 고친다.

> **v0.2 — 단순화.** v0.1 은 5개 섹션 + 조건 분기였다. 아직 이용자가 없는 베타에 과했고,
> 응답자에겐 단계가 늘고 혼자 운영하는 입장에선 폼 관리가 짐이 된다. **단일 섹션**으로 줄였다.
> **v0.3 — 자동 채움 질문 제거.** 이 폼은 **푸터 전용 범용 창구**라 페이지·기기 정보를 담지 않는다.
> 최종 **단일 섹션 4문항**. 문의가 실제로 쌓여 분류가 필요해지면 그때 섹션을 나눈다.
> `foot.js` 는 그대로 둔다 — `CS_ENTRY_CTX` 를 빈 값으로 두면 미리채우기 없이 폼만 열도록 이미 되어 있다.

## 0. 왜 폼이 따로 필요한가

이미 있는 폼 둘은 **오류 제보 전용**이고, 값어치는 "무엇이 잘못됐는지"를 **자동으로 담아 보내는 것**에 있다.

| 폼 | 자동 채움 | 진입점 |
|---|---|---|
| playground | 격자·나무 개수·모양 링크·UA | playground 우하단 "의견" FAB, **이 폼 설명문의 링크** |
| quiz/run | 유형·난이도·문항 번호·보기 형태·재현 링크·기기 | 문항 헤더 제보 버튼 |

**CS 폼이 오류 제보를 같이 받으면 그 자동 컨텍스트가 통째로 사라진다.**
그래서 CS 폼은 오류 제보를 **설명문에서 전용 폼으로 돌려보낸다**(분기 대신 안내로 — 그게 더 싸다).

**CS 폼은 playground·404 를 제외한 전 페이지(9곳) 푸터의 문의 창구다.**
랜딩 '정보' 열의 '의견 보내기'(playground 폼)도 260828 에 이 폼으로 교체했다 —
한 푸터에 비슷한 창구를 둘 두지 않기 위해서다. playground 오류 폼은 playground 화면의
'의견' 버튼과 이 폼 **설명문의 링크**로 여전히 닿는다.

## 2. 질문 (단일 섹션, 위에서부터 이 순서)

### Q1. 어떤 문의인가요? · 객관식 · **필수**
```
계정·로그인
저장한 자료(퀴즈 기록·문제지·모양)
이용권·결제
개인정보 요청(열람·정정·삭제·처리정지·탈퇴)
그 밖의 문의·제안
```
섹션 이동은 **쓰지 않는다.** 분류는 답변 시트에서 보면 충분하다.

### [설명 블록] — Q1 바로 아래
질문이 아니라 "제목 및 설명" 항목으로 넣는다. **짧지만 빼면 안 되는 경고다.**
```
개인정보 요청은 법에 따라 본인확인이 필요합니다. 접수하시면 가입에 사용하신
소셜 계정 이메일로 확인 메일을 보내드리고, 확인 후 10일 이내에 처리합니다.
이 양식 제출만으로는 삭제·탈퇴가 실행되지 않습니다.
```
> 마지막 문장이 핵심이다. 없으면 **타인이 남의 계정 삭제를 요청**할 수 있고, 요청자는 제출만으로 삭제된 줄 안다.

### Q2. 내용 · 장문 · **필수**
설명:
```
언제, 어느 화면에서, 무엇을 하려다 어떻게 됐는지 적어주시면 가장 빠릅니다.
개인정보 요청이라면 가입에 쓰신 소셜 계정(카카오/구글)도 함께 알려주세요.
```

### Q3. 답변받을 이메일 · 단답 · 선택 · **응답 확인: 텍스트 → 이메일**
설명:
```
적지 않으시면 답을 드릴 수 없습니다.
개인정보 요청은 이 주소로 본인확인 메일을 보내므로 반드시 적어주세요.
```

## 4. 폼 생성 후 — 사이트 연동

1. ~~`assets/js/foot.js` 의 `CS_VIEWFORM_URL` 을 채운다~~ — **완료(260828)**
2. ~~`foot.js?v=` 를 올린다~~ — **완료, `v=0.4.0` · 소비처 9곳**
3. 폼 응답 탭 → 스프레드시트 연결, **새 응답 이메일 알림** 켜기 ← **남은 일**

> `CS_ENTRY_CTX` 가 비어 있으면 `foot.js` 는 미리채우기 없이 **폼 주소만** 연다.
> 자동 채움 질문(v0.1 의 Q4)을 빼기로 했으므로 이 값은 계속 비워 둔다.
> 코드는 그대로 두는 편이 낫다 — 나중에 자동 채움을 다시 넣고 싶어지면 상수 하나만 채우면 된다.

### 폼이 없을 때의 동작
`CS_VIEWFORM_URL` 이 비어 있으면 `#csLink` 는 **`mailto:` 로 폴백**하고, 푸터의 이메일 링크(`#csMail`)와 그 구분점은 중복이라 스스로 제거된다. **폼이 준비되기 전에도 푸터가 죽지 않는다.**

## 5. 폼을 고칠 때 함께 볼 곳

문의 창구를 늘리거나 바꾸면 **아래가 같이 움직여야 한다.** 하나만 고치면 화면과 약관이 어긋난다.

| 대상 | 내용 |
|---|---|
| `assets/js/foot.js` | `CS_VIEWFORM_URL` · `CS_ENTRY_CTX` · `CS_MAIL` — **값의 정본** |
| `terms/index.html` 제33조 ② | 문의 창구 열거: 전화 · 전자우편 · **온라인 문의 양식** |
| `privacy/index.html` §5 | 처리위탁 Google LLC 행에 **온라인 문의 양식 운영(Google Forms)** |
| `privacy/index.html` §6 | 국외이전 Google LLC 행에 **문의 시 입력한 내용 및 회신용 이메일** |
| `privacy/index.html` §1 | 수집 항목 "문의 정보" 행 (이미 반영됨) |
| `/account` `.ah-help` | 같은 상수를 쓰므로 자동으로 폼을 연다 |

**폼으로 문의를 받으면 Google 이 그 개인정보의 수탁자가 된다** — 위 §5·§6 갱신을 빠뜨리면 방침이 사실과 어긋난다.

## 6. 일부러 넣지 않은 것

| 항목 | 이유 |
|---|---|
| **섹션 분기** | 이용자가 없는 단계에서 관리 부담만 크다. 오류 제보 라우팅은 설명문 링크로 충분하다 |
| **작성자(보호자/선생님/학생) 질문** | 답을 받아도 하는 일이 달라지지 않는다 |
| **로그인 상태 질문** | 답을 받아도 하는 일이 달라지지 않는다. 필요하면 Q2 에 적힌다 |
| **화면 상황 자동 채움 질문** | 푸터는 어느 페이지에서든 눌리는 **범용 창구**라 페이지·기기 정보를 굳이 담지 않는다. ⚠ **잃는 것**: "어느 화면에서 눌렀는지"가 안 오므로, 화면을 특정해야 하는 문의는 Q2 에 적힌 내용에만 의존한다. 그래서 Q2 설명이 "어느 화면에서"를 먼저 묻는다 — **이 문구를 지우지 말 것** |
| **개인정보 요청 전용 문항 5개** | 건수가 드물고 어차피 이메일 본인확인으로 넘어간다. 경고 블록 + Q2 자유 기술로 충분 |
| **파일 업로드** | 구글 로그인을 강제해 아동·비로그인 사용자를 막는다. 사진은 이메일로 |
| **저작권·권리침해 신고 섹션** | 위임장·권리 증빙 **첨부가 사실상 필수**라 폼으로 받아도 이메일로 되돌려 보내게 된다. 이메일이 맡는다. **약관 제23조 ③(무단 공유 산출물 차단·삭제)은 그대로 유효** — 조치 근거는 남고 접수 경로만 이메일이다 |

문의가 실제로 쌓여 분류·통계가 필요해지면 그때 섹션을 나눈다. **지금 필요한 건 접수되는 창구이지 잘 나뉜 창구가 아니다.**
